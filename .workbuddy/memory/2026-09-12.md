## AUTOSAR CanNm 上位机模拟软件（项目启动 / 方案阶段）

- 需求：Python + PyQt5 的 CanNm 仿真上位机，**纯动画演示、不与实物交互**；多节点 ECU 模拟、NM PDU 收发、Sleep Indication / Sleep Acknowledge、状态可视化、手动唤醒/睡眠、NodeID 与报文周期配置、实时收发 Log。
- 参考规范：`庆铃AUTOSAR CAN网络管理技术规范V1.0.pdf`（21 页，已用 pypdf 提取全文）。
  - 定时参数：T_REPEAT_MESSAGE=1000ms、T_NM_TIMEOUT=3000ms、T_WAIT_BUS_SLEEP=5000ms、T_WakeUp≤100ms、T_START_App_TX=20ms、T_NM_ImmediateCycleTime=20ms、T_NM_MessageCycle=200ms、N_ImmediateNM_TIMES=5、T_WAIT_DiagReq=5000ms。
  - NM PDU：CAN ID 基址 `0x18FFE100` + NodeID（即 ID 后两位）；Byte0=SNI；Byte1 bit0=RMR、bit4=AWB、bit6=PNI；Byte2 低 7 位=网络管理状态码；Byte3=唤醒原因；Byte4=保持事件 AC0_KL15/AC1_Diag/AC2_Tmin/AC3_Remote/AC4_OTA；Byte5~7=PN 标志（规范标注"暂不实施"）。
  - 状态码：1=RMS←BSM、2=RMS←PBS、4=NOS←RMS、8=NOS←RSS、16=RMS←NOS、32=RMS←RSS。
  - 规范待确认点 ①：状态码 16 与 32 的文字描述重复（都写"←ReadySleepState"），需与甲方/网络组确认。②：T_WakeUp 在表 4 中出现 100ms 与 200ms 两个值，需确认适用值。
- 已确定技术方案：core 层零 Qt 依赖（可单测、后续可接 python-can 接实物）；单一全局时钟 tick 驱动全部节点；Qt 信号槽向 UI 推送状态与日志；UI 分层文件结构（ui / presenter / core / config）。
- 规范中**未定义** Sleep Indication / Sleep Acknowledge 位（控制比特向量只有 RMR/AWB/PNI）。该概念属于 AUTOSAR 通用 Nm 层回调（Nm_RemoteSleepIndication / Cancellation / Confirmation）或 OSEK 风格 NM。本项目按"可选叠加信号"实现并在 UI 上显式展示。
- 进展：已向用户确认状态机理解并给出项目文件结构，等待确认后搭建骨架。

## 阶段四：用户提问「点 KL15 主动唤醒后一直在 NOS」

- **结论：不是 bug，是规范语义。** KL15 是**网络保持事件**（Byte4 的 AC_0_KL15），不是一次性脉冲；
  只要 keep_awake 里还有 KL15，节点就停在 NOS：每 1000ms 发一帧、每帧都重启 T_NMTimeout，
  而 T_NMTimeout 是唯一能把节点推进 PBS 的定时器（T_REPEAT_MESSAGE 只在 RMS 里存在）→ NOS 没有任何自动出口，
  必须应用层调 CanNm_NetworkRelease() 清除需求。
- 实测证据（20 秒仿真、只点一次唤醒）：2000/8000/20000ms 三个采样点全是 NOS，TX 24 帧不变。
  对照实验（第 6 秒点释放）：NOS→RSS@6000 → PBS@8000 → BSM@13000。
- **顺手改掉的 UX 缺陷**：控制区新增「当前网络需求：KL15 / 无」实时指示（琥珀色高亮），
  「释放网络」按钮改为**仅在存在需求时可点**；两个按钮加了 tooltip 说明语义；控制区底部提示写清
  "想让它睡下去必须点释放，之后约 7 秒走完 RSS→PBS→BSM"。
- 新增 2 项界面回归测试：`test_demand_indicator_and_release_button`、
  `test_kl15_keeps_node_in_nos_until_released`（断言未释放时日志里不出现 PBS）。UI 测试 7 项，全量 26 项。
- README：新增 FAQ Q3（附实测时间线表格），原 Q3~Q10 顺延为 Q4~Q11；5.2 节补充需求指示说明。

## 阶段五：KL15 电源开关 + 发现并修复 AWB 规范偏差

  ② 接口级控制：唤醒源（移除了 KL15，只留外设 I/O / 功能唤醒）+ 主动唤醒 + 当前网络需求 +

- **新增开关与引擎快照的同步防抖**：用户点击后 300ms 内不回读开关状态（`KL15_SYNC_GRACE_S`），
  否则下一批快照可能还是点击前的旧值，会把用户刚勾上的开关又弹回来。断开连接时强制复位为「下电」。
- **发现并修复一个真实规范偏差（AWB）**：规范 4.6.4 要求 AWB 置 1 后"**直到其进入预睡眠状态(ReadySleepState)**"才清零，

  实测修复后：RMS awb=1 → NOS awb=1（保持）→ RSS awb=0。
