## 1. 运行模式与状态

| 顶层模式 | 状态 | 简称 | 说明 |
| --- | --- | --- | --- |
| BusSleepMode | 总线睡眠模式 | BSM | 仅保留唤醒能力，不参与应用报文收发 |
| PrepareBusSleepMode | 准备总线睡眠模式 | PBS | 清空发送缓存，等 T_WAIT_BUS_SLEEP |
| NetworkMode | 重复报文状态 | RMS | 进入网络模式后的默认状态，快速发送机制 |
| NetworkMode | 常规运行状态 | NOS | 有网络需求期间持续周期发送 |
| NetworkMode | 预睡眠状态 | RSS | 停发 NM 报文，等 T_NMTimeout 静默 |

## 6. Byte3 唤醒原因

| 编码 | 含义 |
| --- | --- |
| 0 | 初始化（仅首帧允许，最迟第二帧须为实际值） |
| 1 | 总线唤醒 |
| 2 | KL15上电 |

3~127 为外设 I/O 唤醒，128~255 为功能唤醒，具体编码由网络组释放后补充。

## 7. 待客户确认清单

1. **NM Remote Sleep Indication Bit 的位序**：客户规范提及该位但未给出位置，
   当前占位在 Byte1 bit3（配置驱动，确认后改一行即可）。
2. **AC_4_OTA 的位序**：规范表格中写作 AC_3_OTA，疑为笔误，当前按 Byte4 bit4 处理。
3. **Byte2 状态码 16 与 32**：规范中两条的说明文字重复，当前按 16 = RMS←NOS、
   32 = RMS←RSS 推断，但 8 已是 NOS←RSS，存在冲突。
4. **T_WakeUp 取值**：规范表 4 中同时出现 100ms 与 200ms 两个值，当前取 100ms。
5. **RSS 收到本地唤醒的出口状态**：4.3.3.3 要求进 NOS，部分网络章节 NM_15 要求进 RMS
   快速发送；当前默认按 4.3.3.3 进 NOS，可用配置项切换。
6. **进入 RSS 是否补发一帧睡眠指示**：因 RSS 本身停发 NM 报文，若不补发则该位无法广播；
   当前默认补发一帧，可用配置项 `send_sleep_indication_on_rss` 关闭。
7. **诊断报文能否在 BSM / PBS 下唤醒网络**：规范表 4 中这两个状态的「应用报文 Rx」为 N，
   即根本不接收诊断报文，因此**默认不能**；诊断只能把 RSS 拉回 NOS（4.3.3.3）。
   若客户要求诊断仪可直接唤醒网络，把配置项 `diag_can_wake_from_sleep` 置为 true，
   行为与 RSS 一致（直接进 NOS 并启动 T_WAIT_DiagReq），但会绕过「默认先进 RMS」的规则。
